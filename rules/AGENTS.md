# Antigravity Booster (`agb`) Session Orchestration Rules

When the `antigravity-booster` plugin is enabled in this workspace, prefer its deterministic multi-agent orchestration tools (`call_mcp_tool` on server `antigravity-booster_agb`, or eager `mcp_antigravity-booster_agb_status` / `mcp_antigravity-booster_agb_doctor`) and `/agb` (or `/agb-*`) skills whenever a task spans multiple files, independent subsystems, or pre-merge verification:

0. **Umbrella Natural-Language Router (`/agb <description>`)**
   - Users can invoke `/agb <description>` (or `/antigravity-booster:agb <description>`) with any natural-language task or subcommand (`shape`, `plan`, `run`, `review`, `distill`, `doctor`, `init`, `bootstrap`, `migrate`, `sidecar`, `status`, `watch`, `preflight`, `validate`, `pool`, `brains`, `sweep`, `sync-models`, `rescue`, `accept`, `holdout`) and it automatically routes to the right `agb` workflow.
1. **Environment & First-Run Readiness (`agb_doctor` / `/agb-doctor`, `agb_init`, `/agb-bootstrap`)**
   - Before starting a fleet run or if `agb` reports a missing runtime/companion plugin, invoke `mcp_antigravity-booster_agb_doctor` (or `/agb-doctor`). Use `call_mcp_tool(ServerName="antigravity-booster_agb", ToolName="agb_init", ...)` to scaffold `.adlc/config.json`, `specs/feature-template.md`, and `.gitignore` in a new repo. If `~/.local/bin/agb` is not yet installed, instruct the user to run `/agb-bootstrap` once.
2. **Spec Shaping & Spec-to-DAG Decomposition (`agb_shape` / `/agb-shape`, `agb_plan` / `/agb-plan`)**
   - When starting from a raw feature concept or spec, shape and pre-analyze the ticket DAG with `agb_shape` (`ServerName="antigravity-booster_agb"` or `/agb-shape`), then compile the spec into a validated `plan.json` ticket DAG using `agb_plan` (`ServerName="antigravity-booster_agb"` or `/agb-plan`, optionally passing `--emit-workflow <file.py>` / `emitWorkflow` to generate a native `run_workflow` Python script) so scope overlap, cold-start executability, parallax interface contracts, and frozen rails are verified before build tokens are spent.
3. **Quota-Pool-Aware Parallel Execution (`agb_run` / `/agb-run`)**
   - Execute validated `plan.json` ticket DAGs via `agb_run` (`ServerName="antigravity-booster_agb"` or `/agb-run`) to dispatch isolated git-worktree builders across `Gemini` and `Claude` quota pools with mechanical `PreToolUse` rail protection and serialized merge gates.
   - Recommend `/agb-sidecar` (or `agb_flight_deck` in Antigravity Desktop) when the user wants live visual telemetry of the ticket DAG, pool saturation, and prosecutor verdicts.
4. **Cross-Model Pre-Merge Prosecution (`agb_review` / `/agb-review`)**
   - Before declaring a non-trivial branch ready to merge, run `agb_review` (`ServerName="antigravity-booster_agb"` or `/agb-review --five-lens`) to prosecute the diff across five orthogonal lenses (`correctness_redteam`, `security`, `simplicity`, `evidence_runner`, `anti_slop`) with cross-family or fresh-context prosecution.
5. **Distilling Recurring Findings into Learned Defenses (`agb distill` / `agb_distill`)**
   - After fleet runs or adversarial reviews, invoke `agb_distill` (`ServerName="antigravity-booster_agb"` or `agb distill [repo] [--apply] [--compile-checks]`) to scan review and prosecution logs for recurring patterns and stage or apply compacted ADLC defenses to `.agents/rules/adlc-learned.md` (with `trigger: always_on` frontmatter) and `.adlc/learned-checks.json`.
