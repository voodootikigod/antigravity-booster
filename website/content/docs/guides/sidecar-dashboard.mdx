The sidecar is a small local web dashboard that streams a run's events into an Antigravity sidecar panel alongside the terminal [`agb watch`](/docs/reference/cli/watch) dashboard. It is opt-in: `agb bootstrap` does not install it; you start it when you want it.

## Start it

<Steps>
<Step>

### Launch the server

```bash
agb sidecar                 # repo defaults to the current directory
agb sidecar /path/to/repo --port 4000
```

The repo argument is optional and defaults to `.`. The port comes from `--port`, else `AGB_SIDECAR_PORT`, else `3333`; it must be an integer from 0 to 65535, and `0` asks the OS for a free port. Any other `--` flag is rejected. The server binds to `127.0.0.1` only and prints `AGB Sidecar Dashboard URL: http://127.0.0.1:<port>/?token=<token>` (when running `sidecars/server.mjs` directly, it logs `AGB Sidecar Server running at http://127.0.0.1:<port>`).

</Step>
<Step>

### The token URL

Each launch generates a fresh random session token and prints the authenticated dashboard URL `http://127.0.0.1:<port>/?token=<token>` directly to stdout (v2.0.0 removed `agb-sidecar-plugin-*` dynamic manifest creation and `agy plugin install`/`uninstall` registration). Because stdout contains the session token, avoid forwarding `agb sidecar` output into shared CI or transcript logs. Requests to `/` and `/index.html` require `?token=`; `/events` accepts `?token=` or `Authorization: Bearer`. Comparisons are constant-time.

</Step>
<Step>

### Watch a run

Start a run in another terminal (`agb run plan.json`). The dashboard reads `.booster/run.json` to find the current `runId` and tails `.booster/logs/<runId>/events.jsonl`.

</Step>
</Steps>

## Stopping

Press `Ctrl+C` or send `SIGTERM`. On exit the HTTP server closes cleanly (`130` on `SIGINT`, `143` on `SIGTERM`).

## What the server serves

- Only `/`, `/index.html`, `/app.js`, `/style.css` and `/events`; any other path is `403` ([allowlist](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/sidecars/server.mjs#L142-L149)).
- Requests whose `Host` is not `127.0.0.1`, `localhost` or `::1` are rejected with `403` ([host check](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/sidecars/server.mjs#L13-L22)).
- `/app.js` and `/style.css` are served without a token check.

## Jetski mode and ANTIGRAVITY_SIDECAR_WEB_PORT

`ANTIGRAVITY_SIDECAR_WEB_PORT` is a real variable. When it is set, the bundled `sidecars/jetski-launcher.mjs` runs in unauthenticated Jetski mode (`token = null`) and listens on that port (default `3333`) (jetski mode: [C3](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/sidecars/jetski-launcher.mjs#L8-L9)).

<Callout type="warn" title="ANTIGRAVITY_SIDECAR_WEB_PORT and token authentication">
`sidecars/server.mjs` and `agb sidecar` **always enforce explicit tokens** regardless of whether `ANTIGRAVITY_SIDECAR_WEB_PORT` is set (historically in v1.0.0, setting it bypassed the server token check directly: [C3](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/sidecars/server.mjs#L32), [/events bypass](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/sidecars/server.mjs#L43)). Today, `ANTIGRAVITY_SIDECAR_WEB_PORT` only causes `sidecars/jetski-launcher.mjs` to launch in unauthenticated Jetski mode (`token = null`), where any local process that can reach the port can read your run's events. Do not export it in a shell where you launch Jetski. The threat model is in [Security](/docs/reference/security).
</Callout>
