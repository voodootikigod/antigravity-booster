`agb` exists to apply the Agentic Development Lifecycle (ADLC) to other repositories, and this repository follows it too. The rules for contributors and agents are in [AGENTS.md](https://github.com/voodootikigod/antigravity-booster/blob/main/AGENTS.md). This page explains how they are enforced.

## Tickets come first

Non-trivial work starts as a ticket in the `.adlc/tickets/` directory store, one file per ticket, created with `adlc ticket create`. A ticket names its `scope` (paths it may change), its `rails` (paths that must not change while it is open) and its `edges` (dependencies). See [Rail enforcement](/docs/concepts/rail-enforcement) for how agb uses these fields.

## Frozen rails

The rails of every active ticket are combined, and those paths are frozen. Two layers enforce this:

- **In session:** the PreToolUse policy guard blocks edits to frozen paths before they happen ([Policy guard](/docs/internals/policy-guard)).
- **In CI:** [`adlc-rails-guard.yml`](https://github.com/voodootikigod/antigravity-booster/blob/main/.github/workflows/adlc-rails-guard.yml) runs on every pull request. It runs `adlc rails-guard` against the rails declared by active tickets on the trusted base branch, so a write the hook missed is still rejected.

Two files are always treated as rails here: `lib/lock.mjs` (merge-lock correctness) and `lib/gates.mjs` (sandbox enforcement). To check a change locally, run `adlc rails-guard --base <ref> --rails <globs>`.

<Callout type="info">
CI reads rails from the `.adlc/tickets/` directory store since #87 ([scripts/rails-guard-ci.mjs](https://github.com/voodootikigod/antigravity-booster/blob/a99b3cd/scripts/rails-guard-ci.mjs#L256)), which landed after v1.0.0. At v1.0.0 the workflow read only the legacy `.adlc/tickets.json`.
</Callout>

## CI protects itself

A pull request runs the workflow files from its own branch, so a PR could otherwise disable the gate that checks it. Three things prevent this:

- [CODEOWNERS](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/CODEOWNERS#L6) assigns `.github/workflows/**`, the bundles, hooks, `.adlc/**` and the ADLC bridge files to the owner. Branch protection on `main` requires Code Owner review and applies to admins too.
- The rails-guard job treats `.adlc/config.json`, `CODEOWNERS` and its own workflow and script as fixed trust roots ([adlc-rails-guard.yml#L384](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/.github/workflows/adlc-rails-guard.yml#L384)).
- [`ci.yml`](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/.github/workflows/ci.yml#L102) rebuilds `dist/` and `vendor/` and fails if they differ from the committed copies. It also checks that the vendored `@adlc/antigravity` tarball is byte-identical to the npm release ([ci.yml#L115](https://github.com/voodootikigod/antigravity-booster/blob/v1.0.0/.github/workflows/ci.yml#L115)).

Only a person may set the `acknowledgedNewRailBypass` and `trustedCodeownersAttested` fields in `.adlc/config.json`, and only after explicitly confirming that exact change. An agent never sets them.

## Prosecution before done

A change counts as done only with evidence. That means `npm test` output, `adlc hollow-test` for changes under `lib/`, and gate records added with `adlc gate-manifest record`. See [Prosecution](/docs/concepts/prosecution) and [Gate evidence](/docs/concepts/gate-evidence).

## Archive on merge

The ticket store holds only active work. In the CI gate, a completed ticket's rails no longer count, but they still block edits in session until the ticket is archived. After a ticket's PR merges, a follow-up chore PR runs:

```sh
npx adlc ticket complete <id> --write --authorize
npx adlc ticket archive <id> --write --authorize
```

The CI gate allows a PR to make only these changes to existing base tickets: mark one `completed: true`, or move it to `.adlc/ticket-archive/` ([rails-guard-ci.mjs#L180](https://github.com/voodootikigod/antigravity-booster/blob/a99b3cd/scripts/rails-guard-ci.mjs#L180)). Merging to `main` is always a person's decision.
